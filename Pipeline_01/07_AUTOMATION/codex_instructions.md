# Codex Instructions

## Obiettivo
Usare il vault come memoria operativa del progetto, non solo come archivio note.

## Leggere prima di lavorare
1. [[../11_MEMORY/INDEX]]
2. [[../11_MEMORY/PROJECT_STATE]]
3. [[../11_MEMORY/DECISIONS_LOG]]
4. [[../11_MEMORY/DEVELOPMENT_BACKLOG]]
5. [[../11_MEMORY/ASSISTANT_CONTEXT]]

## Regole operative
1. Ogni test o analisi importante -> nuovo file `.md`
2. Salvare il file nella cartella giusta
3. Mai sovrascrivere risultati storici
4. Aggiornare la memoria centrale se cambia una decisione, un target o una priorita
5. Segnalare sempre incoerenze tra documenti invece di nasconderle
6. Se un file citato non esiste nel vault, annotarlo come gap

## Naming suggerito
- `test_fft_[asset]_[tf]_[date].md`
- `test_[concept]_[asset]_[tf]_[date].md`
- `note_[topic]_[date].md`

## Output minimi da salvare
- ipotesi testata
- dati usati
- parametri
- metriche
- risultato finale
- decisione: promuovere, scartare o ripetere
